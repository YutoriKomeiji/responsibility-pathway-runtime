Scenario

Preserve responsibility after the effect becomes uncertain

1. Register the responsibility pathway

RPR records who may approve and execute, where unresolved work can return, and who remains the Residual Owner. A high-impact action first enters human_gate, visible as bounded_human_return.

2. Create an ambiguous external effect

After approval, the provider is called once. The provider applies the effect, but the response is lost. RPR persists write_status_unknown, visible as hold_for_reconciliation.

3. Restart and reconcile

A fresh runtime reopens the same SQLite state, checks the provider, and completes without re-dispatching the operation. Completed state is not assigned an unreviewed compatibility route.

Responsibility Routing

Route visibility is an observation surface, not an Authority transfer

Human Return is one bounded route

bounded_human_return represents cases that really need a human decision or human-held Authority. It is not the universal destination for every non-autonomous case.

Unknown effects stay in reconciliation

write_status_unknown is not silently converted into success, failure, or a retry. The unresolved effect remains visible as hold_for_reconciliation.

Evidence transfer ≠ Authority transfer

rpr.get_route_visibility is read-only. Its structured result carries authority_inferred: false. A receiver name, capability, evidence item, tool success, or route display does not create new Authority.

Scope

What is real and what is simulated

Real in this demo

CI-built RPR wheel, Python Runtime API, transition checks, SQLite persistence, attempt history, evidence chain, restart readback, reconciliation, and read-only MCP route visibility.

Simulated

Only the external payment provider is replaced by a deterministic in-process adapter. Applied state and dispatch count are tracked separately from RPR.

Not demonstrated here

External OS subprocess MCP, secrets, real payments, external service authentication, and Lean 4 builds are not run in the browser. Formal assets remain verified in the repository and CI.
