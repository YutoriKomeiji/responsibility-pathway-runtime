MIT-licensed Public Alpha · published 0.1.0a6

Keep the responsibility path intact when software acts.

RPR is a Python runtime for applications that need explicit Authority, attempt continuity, independent readback, fail-closed ambiguity handling, repair/reconciliation, and Responsibility Routing around consequential external actions. Human Return is one bounded route, not the generic fallback for every uncertainty.

Verified locally executable scope

A runtime boundary built for uncertainty, not optimistic completion.

Explicit Authority

Retain actors, declared Authority, pathway state, and authorized transitions instead of reducing governance to a boolean check.

Attempt continuity

Bind operations, attempts, and idempotency identity across retry, restart, repair, and reconciliation.

Independent readback

Completion requires evidence from the affected domain rather than trusting a dispatch response alone.

Fail-closed ambiguity

Post-dispatch uncertainty remains write_status_unknown; RPR does not silently replay an unresolved effect.

Responsibility Routing

Published 0.1.0a6 distinguishes reconciliation hold, eligible delegated receivers, bounded Human Return, and stop/preserve outcomes without inferring Authority from capability or evidence transfer.

Operational evidence

Verified paths include HTTP, MCP subprocess, restart, backup/restore, diagnostics, removal, and retained customer data.

Integration model

RPR governs the pathway. Your host governs the deployment.

The host application remains responsible for authentication, credentials, network and storage controls, bypass prevention, domain-specific authorization, receiver eligibility, delegation source-of-truth, and the independent readback source.

RPR owns pathway lifecycle, execution-attempt continuity, evidence retention, fail-closed ambiguity, route metadata, and explicit return/hold semantics. Fail closed does not mean send to a human. An unresolved or invalid route can remain on neutral hold until eligibility and Authority are established.

RPR does not claim to be

  • a legal-responsibility engine;
  • an identity provider or secret manager;
  • a production gateway or network sandbox;
  • a universal exactly-once guarantee;
  • a source of organizational Authority merely because a receiver is capable or selected;
  • customer-environment verified before that environment is tested.

Current MCP support

Govern outbound MCP tool calls without pretending the response proves the effect.

Published 0.1.0a6 includes subprocess launch, stdio transport, JSON-RPC framing, server/tool admission binding, execution-attempt continuity, fail-closed ambiguous outcomes, the local read-only rpr-mcp inspection server, and read-only Responsibility Routing visibility.

For consequential tools, a successful MCP response is not enough by itself; required independent readback still controls completion.

Current boundary

  • local subprocess and stdio outbound paths are implemented;
  • server identity, capabilities, and tool schema are bound before dispatch;
  • ambiguous outcomes remain unresolved instead of being retried silently;
  • a published local stdio read-only MCP inspection server is available through rpr-mcp;
  • rpr.get_route_visibility is published and remains read-only;
  • remote MCP transport is not claimed.

Operational demonstration

A real failure-and-recovery path, not a mocked success screen.

The browser demo loads the CI-built RPR wheel into Pyodide and runs the actual runtime, SQLite persistence, attempt history, unknown-write handling, restart recovery, reconciliation, and Responsibility Routing visibility. Only the external provider is simulated.

Required outcomes

  • a configured bounded Human Gate appears only where required;
  • ambiguous post-dispatch failure remains unresolved;
  • restart does not duplicate the effect;
  • independent readback resolves the pathway;
  • route visibility does not infer Authority;
  • evidence and Residual Owner remain inspectable.

Quick Start

Install the pinned published Public Alpha from PyPI.

Published 0.1.0a6 is the current package baseline. Repository source can contain later work that is not released until a fresh candidate passes exact-head validation and Human Gate.

python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install responsibility-pathway-runtime==0.1.0a6
rpr --help
rpr-mcp --help
