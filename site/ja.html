AIの外部操作を、止める。確かめる。責任の行き先を曖昧にしない。

RPRは、AIエージェントや自動処理がファイル、API、メッセージ、業務システムを変更するときに、誰のAuthorityで実行したか、何が起きたか、結果をどう確かめたか、失敗後にどのResponsibility Routeで処理を継続するかを一つの経路として残すPython Runtimeです。Human Returnはbounded routeの一つであり、すべての不確実性のgeneric fallbackではありません。

RPRが扱うこと

「たぶん成功した」「人に返せば安全」で処理を終わらせない。

外部systemへのwriteは、通信が切れた瞬間に成功か失敗か分からなくなることがあります。RPRは、その不確実さを消さずに保持し、二重実行を避けながら確認・修復・Responsibility Routingへつなぎます。

Explicit Authority

重要な操作はdeclared Authorityとauthorized transitionに従います。Evidence transferやreceiver capabilityだけでAuthorityは増えません。

Attempt continuity

Operation、attempt、idempotency identityを保存し、restartやretry後も同じ外部作用を無自覚に二重実行しません。

Independent readback

関数の戻り値やHTTP/MCP応答だけで完了にせず、変更先をreadbackして期待したeffectを確認します。

Fail-closed ambiguity

Write後に通信が切れた場合はwrite_status_unknownとして保存し、根拠のない成功判定や自動再送を防ぎます。

Responsibility Routing

公開済み0.1.0a6はreconciliation hold、eligible delegated receiver、bounded Human Return、stop/preserveを区別します。Fail closedは自動的にHuman Gateを意味しません。

Residual ownership

未解決effectや元に戻せない影響が残る場合も、unresolved payloadとResidual Ownerを暗黙に消しません。

RPRと導入側の役割

RPRだけで、system全体の安全やAuthorityが完成するわけではありません。

RPRはexternal actionのstate、Authority境界、Evidence、結果不明、repair、resume、Responsibility Routing metadataを管理します。一方、認証、credential、network、storage、業務rule、receiver eligibility、delegation source-of-truth、readback sourceは導入側で設計します。

Fail closedは「人に返す」と同義ではありません。 Eligible receiverやAuthorityが確立できない場合はneutral holdが正しいことがあります。

RPRが行わないこと

  • 法的責任やorganizational Authorityの自動生成
  • 認証基盤や秘密情報の管理
  • network隔離や本番gatewayの代替
  • あらゆるexternal serviceでの完全な一回実行保証
  • receiverがcapable/selectedという理由だけでAuthorityを付与すること
  • 未検証環境での安全性や適合性の保証

現在のMCP対応

MCPの応答だけで「external effectも成功した」と決めない。

公開済み0.1.0a6は、Local MCP Serverへのoutbound経路、read-only rpr-mcp inspection server、read-only Responsibility Routing visibilityを含みます。Subprocess、stdio、JSON-RPC framing、Server/Tool binding、Execution Attempt continuity、ambiguous outcomeのfail-closed処理を提供します。

変更を伴うToolでは、必要なreadbackなしにcompletionへ進みません。

MCP統合ガイドを読むMCPの動作結果を報告する

現在の境界

  • Local subprocessとstdioのOutbound経路を実装済み
  • Server Identity、Capability、Tool Schemaを実行前にbinding
  • 結果不明のCallを黙って再送しない
  • rpr-mcpのlocal stdio read-only inspection serverを公開済み
  • rpr.get_route_visibilityをread-onlyで公開済み
  • Mutating MCP Server ToolとRemote MCP Transportは未主張

ブラウザで動く実RPRデモ

状態遷移の見本ではなく、CI-built wheelをその場で実行します。

デモページは、GitHub ActionsでRPR sourceから生成したwheelをPyodideへ読み込み、browser内で実際のRPR、SQLite、attempt ledger、Evidence chain、unknown-write、restart、reconciliation、Responsibility Routing visibilityを動かします。

External providerだけは安全なsimulated providerへ置き換えています。RPR本体はmockではありません。

導入方法

公開済み0.1.0a6をPyPIから、影響のない環境で試してください。

Repository sourceには次release向けworkが含まれる場合があります。Fresh candidateのexact-head validationとHuman Gateを通過するまで、公開packageと未公開sourceを同一視しません。

python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install responsibility-pathway-runtime==0.1.0a6
rpr --help
rpr-mcp --help
