# RPR 0.1.0a5 PyPI tag-ref recovery

Purpose: recover the already-authorized `0.1.0a5` PyPI publication after the GitHub prerelease was created successfully but the normal `release: published` downstream workflow did not start because the release was created with `GITHUB_TOKEN`.

Observed follow-up:

- a bounded `main`-ref fallback built and validated distributions successfully;
- the `pypi` environment rejected the publish job before runner steps began;
- the prior successful `0.1.0a4` Trusted Publisher path used the release tag ref.

Recovery:

- temporarily accept `release: edited` in addition to `release: published`;
- admit publication only for exact tag `v0.1.0a5`;
- keep `workflow_dispatch` build-only;
- edit/update the existing GitHub prerelease once so GitHub emits a tag-bound release event;
- require successful PyPI public readback before any public-current surface is promoted to `0.1.0a5`;
- after successful publication/readback, remove the temporary `edited` trigger.

This document does not authorize any later release or stronger product claim.
