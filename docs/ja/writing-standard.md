# RPR 日本語ドキュメント執筆基準

この文書は、RPRの日本語ドキュメント、製品ページ、デモUIへ適用する執筆基準です。

共通原則は、RPPの「日本語ネイティブ技術コミュニケーション・フレームワーク」に基づきます。RPR Repositoryでは、公開製品として必要な技術精度、証拠境界、MIT License上の非保証を加えた本プロファイルを使用します。

## 1. 読者が先に知りたいことを書く

RPRの内部構造より先に、利用者が解決したい問題を示します。

| 内部起点 | 利用者起点 |
|---|---|
| `write_status_unknown`を永続化する | APIが成功したか分からない状態を保存する |
| reconciliationを実行する | 外部システムの状態を読み直して結果を確かめる |
| execution attemptを保持する | いつ、何を、何回実行したかを残す |
| Human Gateを要求する | 人間が承認するまで外部操作を始めない |

正式な状態名や型名は、意味を日本語で説明した後に示します。

## 2. RPR固有語の基準表記

| 実装語 | 日本語本文での基準表記 |
|---|---|
| Responsibility Pathway | 責任経路 |
| Runtime | Runtime |
| pathway | 責任経路 |
| execution attempt | 実行履歴。型や台帳を指すときはexecution attempt |
| evidence chain | 証拠チェーン |
| readback | 読み戻し、または外部状態の再確認 |
| reconciliation | 照合 |
| repair | 修復 |
| resume | 再開 |
| residual owner | 残った影響を引き受ける担当者 |
| `write_status_unknown` | 結果不明（`write_status_unknown`） |
| provider | 外部サービス。adapter説明ではproviderを併記できる |
| dispatch | 外部サービスへの実行。コード説明ではdispatchを併記できる |

同じ段落で、日本語、英語、カタカナを無秩序に切り替えません。

## 3. 製品ページとデモUI

### 見出し

見出しだけで、利用者が何を確認できるか分かるようにします。

| 避ける | 推奨 |
|---|---|
| LIVE EXECUTION | 実際のRPRで復旧まで試す |
| Pathway登録 | 実行前の責任経路を登録する |
| Runtime再生成と照合 | 再起動して結果を確認する |
| 曖昧writeを発生 | 結果不明を発生させる |

### ボタン

ボタンには、押した後に利用者が確認できる動作を書きます。

- RPRを読み込む
- 責任経路を登録する
- 結果不明を発生させる
- 再起動して結果を確認する
- 最初からやり直す

### 実物と模擬

デモでは、何が実物で何がテスト用かを一文ずつ分けて書きます。

推奨:

> RPRのPython package、SQLite、実行履歴、証拠チェーン、照合処理はブラウザ内で実際に動作します。
>
> 外部の決済サービスだけを、安全に試せるテスト用処理へ置き換えています。

## 4. GitHubドキュメント

手順文書は、次の順で書きます。

1. この手順で何ができるか
2. 前提条件
3. 実行するコマンド
4. 確認する結果
5. 失敗した場合の確認先
6. 対象外と非保証

コマンド、パス、状態名、ハッシュ、Version、Freeze IDは英語版と一致させます。説明順と見出しは、日本語の読み手に合わせて変更できます。

## 5. 主張と証拠

次の語は、範囲と証拠を同じ節に示せる場合だけ使用します。

- 検証済み
- 実動
- 再現可能
- 二重実行を防ぐ
- 安全
- 本番対応
- 保証

例:

> ブラウザデモでは、CIで生成したRPR wheelをPyodideへ読み込みます。SQLiteへ結果不明状態を保存し、新しいRuntimeから読み戻して、再送せずに照合を完了するところまでChromium E2Eで確認しています。

この文は、一般的な本番安全性、法令適合、任意の外部サービスでのexactly-onceを意味しません。

## 6. 最終確認

- [ ] 冒頭に利用者の困りごと、目的、得られる結果のいずれかがある
- [ ] 名詞を三つ以上つないだ見出しを避けた
- [ ] 英語の語順を日本語へ持ち込んでいない
- [ ] 技術語を日本語で説明してから実装語へ接続した
- [ ] 実物、模擬、未確認を分けた
- [ ] コード識別子、コマンド、URL、Version、Freeze IDが正しい
- [ ] MIT Licenseの無保証を弱める表現がない
- [ ] 英語版と機能、制約、手順、証拠が一致する
